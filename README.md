# Энергоэстафета

Минимальная автономная миссия для двух Clover 5. Это обычные Python-скрипты:
ROS2-пакет, `colcon build` и установка проекта не нужны.

## Файлы

```text
main.py       конечный автомат БВС-1 и БВС-2
config.json   роль, координаты, сеть, LED, GPIO и таймауты
run.sh        проверка, запуск миссии и отправка управляющих событий
scripts/      независимые тесты ArUco и симуляционного серво
logs/         JSONL-логи попыток, создаются автоматически
```

## Перед полётом

На каждом дроне должна лежать своя копия `config.json`.

1. Установить `active_profile` в `field`.
2. На первом дроне указать `role: "uav1"`, на втором — `role: "uav2"`.
3. Заполнить все `x/y` в `profiles.field`.
4. Заполнить `network.station_ip`, `uav1_ip`, `uav2_ip`.
5. Проверить BCM-номер GPIO серво, направления `open_value/closed_value`.
6. Отдельно проверить LED и установить `required_before_takeoff: true`.
7. Только после проверок установить `flight_enabled: true`.

Проверка конфига не запускает моторы:

```bash
./run.sh check
```

Обычный запуск на каждом дроне:

```bash
./run.sh
```

Оба процесса сначала ожидают UDP-событие `START`. С ноутбука:

```bash
./run.sh signal START <IP-БВС-1> <IP-БВС-2>
```

После зарядки БВС-1 команда с клавиатуры отправляется так:

```bash
./run.sh signal RETURN_HOME <IP-БВС-1>
```

БВС-1 самостоятельно отправит `UAV2_DEPART` второму дрону. Зарядная станция
должна отправлять `LAND_GRANTED` на IP дрона после автономного распознавания:

```bash
./run.sh signal LAND_GRANTED <IP-БВС>
```

Формат UDP-события для контроллера станции:

```json
{"event": "LAND_GRANTED"}
```

Порт задаётся в `network.event_port`.

## Миссия

### БВС-1

1. Жёлтый мигающий, синхронный взлёт.
2. Красный, полёт к зарядной станции.
3. Ожидание `LAND_GRANTED`, посадка и автоматическое выключение моторов.
4. Красный мигающий во время зарядки, зелёный последние 5 секунд.
5. Ожидание `RETURN_HOME`, отправка `UAV2_DEPART`.
6. Зелёный мигающий, взлёт, возврат домой, посадка и disarm.

### БВС-2

1. Жёлтый мигающий, синхронный взлёт и полёт к грузу.
2. Посадка, красный цвет, закрытие захвата.
3. Ожидание `UAV2_DEPART`.
4. Красный, взлёт с грузом и полёт к станции.
5. Ожидание `LAND_GRANTED`, посадка и зарядка.
6. Красный мигающий, открытие захвата.
7. Половина ленты красная, половина синяя; возврат домой и посадка.

Перед глобальной навигацией скрипт сначала взлетает в `base_link`, затем
проверяет стабильный `map -> base_link`. При ошибке выполняется безопасная
посадка. Каждое состояние пишется в отдельный JSONL-лог.

## Серво на Raspberry Pi 5

Для реального профиля используется `gpiozero.Servo` и BCM-нумерация.
По умолчанию указан GPIO18, но его нужно сверить с фактическим подключением.

Серво нельзя питать от сигнального GPIO. Нужен отдельный 5 В источник
достаточной мощности и общий GND между источником, сервоприводом и Raspberry
Pi. После движения PWM отключается через `detach()`, чтобы уменьшить дрожание.

До установки на дрон проверить:

```bash
GPIOZERO_PIN_FACTORY=lgpio python3 -c "from gpiozero import Servo; Servo(18).close()"
```

## Симуляция

Запуск карты:

```bash
ros2 launch clover2_sim gz_simple.launch.py \
  world:=solar_7x7 map_filename:=solar_7x7.yaml gui:=false
```

Безопасная проверка «взлёт — 2 секунды — посадка»:

```bash
./run.sh smoke
```

Профиль должен оставаться `simulation`. В текущем симуляторе ROS LED-драйвера
нет, поэтому индикация логируется как `led_skipped`; на реальном Clover миссия
использует стандартный `/led_strip`.
